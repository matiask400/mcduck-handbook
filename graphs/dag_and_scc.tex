\section{Orden topol\'ogico}
\whenuse{Procesar dependencias de un DAG, hacer DP en grafo dirigido o detectar
ciclos comprobando si se ordenaron todos los v\'ertices.}

Kahn devuelve un orden solamente si el grafo dirigido es un DAG.

\begin{lstlisting}[style=cpp]
vector<int> topological_sort(const vector<vector<int>> &graph) {
    int n = graph.size();
    vector<int> indegree(n, 0), order;
    for (int v = 0; v < n; ++v)
        for (int to : graph[v]) ++indegree[to];

    queue<int> q;
    for (int v = 0; v < n; ++v) if (indegree[v] == 0) q.push(v);
    while (!q.empty()) {
        int v = q.front(); q.pop();
        order.push_back(v);
        for (int to : graph[v]) if (--indegree[to] == 0) q.push(to);
    }
    if ((int)order.size() != n) return {}; // existe un ciclo
    return order;
}
\end{lstlisting}

\complexity{$O(V+E)$ tiempo y memoria.}

\section{Componentes fuertemente conexas (Tarjan)}
\whenuse{Contraer ciclos de un grafo dirigido, obtener su DAG de componentes o
resolver problemas de alcanzabilidad y 2-SAT.}

Tarjan encuentra las componentes en una sola DFS, sin construir el grafo
transpuesto. Esta adaptación de KACTL (Lukas Polacek) conserva el estado dentro de la función
y devuelve \texttt{component[v]}, sin globales ni callback obligatorio.

\texttt{discovery[v]} guarda inicialmente el orden de visita; al regresar
del DFS se reutiliza para el mínimo alcanzable. La pila contiene los vértices
todavía sin componente. El DFS devuelve el menor orden alcanzable dentro de
esa zona activa; si coincide con el de \texttt{v}, se desapila una componente
completa. Las aristas hacia componentes ya cerradas se ignoran.

Tarjan las cierra en orden topológico inverso. Al terminar se invierten los
IDs para conservar el contrato del handbook: si existe una arista $u\to v$
entre componentes distintas, \texttt{component[u] < component[v]}.
Los IDs son consecutivos desde cero; el grafo vacío devuelve un vector vacío.
Esto mantiene compatible la comparación usada por 2-SAT.

\begin{lstlisting}[style=cpp]
vector<int> strongly_connected_components(
        const vector<vector<int>> &graph) {
    int n = graph.size();
    vector<int> discovery(n),stack;
    vector<int> component(n, -1);
    int timer=0,count=0;
    auto dfs = [&](auto &&self,int v) -> int {
        int low=discovery[v]=++timer;
        stack.push_back(v);
        for (int to : graph[v]) if (component[to]==-1)
            low=min(low,discovery[to]?discovery[to]:self(self,to));
        if (low==discovery[v]) {
            int u;
            do {
                u=stack.back(); stack.pop_back();
                component[u]=count;
            } while (u!=v);
            ++count;
        }
        return discovery[v]=low;
    };
    for (int v=0;v<n;++v) if (component[v]==-1) dfs(dfs,v);
    for (int &id : component) id=count-1-id; // Orden topológico del handbook.
    return component;
}
\end{lstlisting}

\complexity{$O(V+E)$ tiempo y $O(V)$ memoria adicional, incluida la pila
recursiva; la lista de adyacencia de entrada ocupa $O(V+E)$.}
\warning{La DFS recursiva puede agotar la pila en grafos muy profundos, como
una cadena larga; en ese caso usar una implementación iterativa.}
